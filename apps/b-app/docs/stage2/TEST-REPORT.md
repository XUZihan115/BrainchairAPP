## 独立算法验证

独立 Python/SciPy 生成原始浮点 EEG、滤波检查点及参考分数，Kotlin 从原始样本自行计算，不读取参考答案参与判决。没有使用 A 端验收器作为依据。固定随机种子用于复现，不代表多被试泛化。

四阶两 SOS 的单位冲激与 SciPy 对照：100、250、500、1000、2000、4000 Hz 六种采样率均通过，最大绝对误差不超过 `1.02e-14`。跨不规则 7/13 样本分块保持滤波状态。八种场景的滤波检查点容差 `1e-8`、CCA 分数容差 `1e-8` 均通过。另测全平坦与秩亏矩阵，未产生虚构的满秩相关。

1000 Hz、9 通道、6 秒合成输入，经连续滤波取最后 4 秒，实测分数如下（四舍五入）：

## 停止、异常和并发

JUnit 实测：通道逆序仍按名识别；重复读取同一窗口不会增加投票；STOP 清空判决；新 INFO 后重新累积；方向改变先停止再投票；低相关/双频模糊/NaN 拒识；参数变更立即停止；缺通道、原始缓冲覆盖、丢包失连续、数据超时均停止。

专门阻塞第四次 CCA 调用，同时继续通过真实本机 UDP socket 以 200 包/秒发送：1600 个样本包和 1 个 INFO 全部接受，缺包 0；此前已稳定前进，独立超时检查在无新判决超过 1 秒后切回停止。由此验证 CCA 不占用 UDP 接收线程，不能据此保证所有手机负载下永不丢包。

Android API35 x86_64 模拟器（内存设置 1536MB）上安装最终 APK，经模拟器 UDP 转发发送另一随机种子、另一相位布局的 62 通道输入：**31/31 检查通过**。

- 四方向分别输入 8 秒；尾部有效窗口均得到对应稳定方向。
- 噪声、弱信号、双频模糊、全零分别输入 8 秒；尾部均为停止。
- 每个场景 STREAM_STOP 后停止，包计数与发送一致。
- 不重发 INFO 连续切换前进→左转，最终左转。
- 主动省略一个样本包，检测到一个缺包；窗口重建期间停止，重新积累后恢复左转。
- 停发 1.3 秒后停止；新 INFO 与右转流后正常恢复。
- 总发送/接收 **19218/19218**，无额外网络丢失。主动省略的一个包不计入实际发送数。

## 实际性能

采样参数：1000 Hz、62 通道、每包 5 样本，发送期间目标 200 包/秒。全场景耗时 **105.087 秒**，包括流间暂停、截图和等待；采集到 219 次不同分析结果。不是数小时压力测试。

| 指标 | 实测 |
|---|---:|
| App 进程 CPU / 一个逻辑核（整个测试区间平均） | 8.30% |
| 每轮分析墙钟耗时：平均 / P95 / 最大 | 3.26 / 4.97 / 9.14 ms |
| 有效判决周期：中位数 / P95 / 最大 | 204 / 207.65 / 414 ms |
| 采样到的 Java 已用堆范围 | 3,756,912–11,289,424 字节（3.58–10.77 MiB） |
| 测试前 / 后进程 TOTAL PSS | 46,824 / 57,575 KiB（45.73 / 56.23 MiB） |

CPU 由 App 进程累计 CPU 时间差除以墙钟时间，包含界面、接收、算法和诊断，不是整台电脑或模拟器 CPU。计算耗时包含取数、滤波和 CCA；周期是实际发布结果间隔，不是定时器配置。观察到少数约 405–414ms 间隔，未承诺硬实时 200ms。内存 PSS 的增长含初始化/JIT 等影响；这段短测不足以证明没有长期泄漏，也不能外推手机功耗。
