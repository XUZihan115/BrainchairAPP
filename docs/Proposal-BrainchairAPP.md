## 1. 项目概述

**项目名称：** 脑控轮椅安卓上位机（BrainchairAPP）
**一句话：** 通过脑机信号（模拟脑电）控制轮椅运动的安卓上位机，用「双手机 + WiFi UDP + Unity 3D 虚拟轮椅」在无真实硬件条件下完成脑控轮椅全链路演示。

## 2. 问题与目标用户

**问题背景：** 手动轮椅依赖体力与上肢功能；电动轮椅摇杆对手部功能有要求，且主流方案成本高、接口封闭，难以低成本教学验证。脑控轮椅以脑电信号驱动移动，是可行方向。

**目标用户：**
- 轮椅使用者：希望以更少的肢体动作完成「前进、转向、停止」等指令；
- 课程评审教师与答辩评委：项目演示与验收对象；
- 照护者：可旁侧监控速度与运行状态。

**使用情境：** 用户佩戴脑电输入（本演示中为 A 手机模拟 SSVEP 解码结果）→ 上位机解析意图与置信度 → 生成控制指令 → 轮椅执行并回显状态。

## 3. 证据

> **证据类型：资料佐证**（课程指南认可的四类证据之一：相关记录/数据佐证）。以下数据均来自可访问的公开来源，附访问日期（2026-10-15），详见 `docs/research-BrainchairAPP.md`。全组须逐条人工核对。

### 3.1 需求规模：轮椅相关人群基数大且增长

- **全球**：WHO/世界银行《World Report on Disability》(2011) 指出全球约 **15%** 人口（超 **10 亿**人）存在残疾，且因老龄化与慢性病持续上升。
  https://www.who.int/teams/noncommunicable-diseases/sensory-functions-disability-and-rehabilitation/world-report-on-disability
- **中国**：中国残联官方推算，2010 年末全国残疾人总数 **8502 万**，其中**肢体残疾 2472 万**（轮椅/机动轮椅车的最主要潜在用户）。
  http://www.cdpf.org.cn/zwgk/zccx/cjrgk/15e9ac67d7124f3fb4a23b7e2ac739aa.htm
- **中国（最新）**：《2023 年残疾人事业发展统计公报》显示当年 **871.8 万**残疾人获基本康复服务，其中肢体残疾 **415.7 万**；为 **22.5 万**残疾人发放机动轮椅车燃油补贴。
  http://www.cdpf.org.cn/zwgk/zccx/tjgb/03df9528fdcd4bc4a8deee35d0e85551.htm

### 3.2 市场与成本痛点：电动轮椅贵、接口封闭

- Mordor Intelligence《Electric Wheelchair Market (2026-2031)》：全球市场 2026 年约 **42.8 亿美元**，预计 2031 年 **67.4 亿美元**（CAGR 9.5%）；高端电动轮椅价格 **8,000~30,000 美元**，年维护成本可达购置价 15~20%，「设备成本高、保险覆盖有限」被列为市场主要制约。
- 同一报告明确：**脑机接口（BCI）试点**正是头部厂商正在推进的差异化方向（为高位损伤患者提供免手控制）。
  https://www.mordorintelligence.com/industry-reports/electric-wheelchair-market

### 3.3 技术可行性：BCI 轮椅控制是成熟研究范式

- arXiv:2404.17895《Empowering Mobility: BCI for Enhancing Wheelchair Control for Individuals with Physical Disabilities》（2024 HCI International）——面向肢体残疾人士的非侵入式 EEG-BCI 轮椅控制闭环。
- arXiv:2106.11008《Wheelchair automation by a hybrid BCI system using SSVEP and eye blinks》（2021 IEEE SMC）——混合 BCI 轮椅原型，原文明确「轮椅由树莓派经 WiFi 控制」，单指令平均 4.015s、成功率 86.97%；**其范式正是 SSVEP 意图选择（注视闪烁目标选方向 + 眨眼停止）——本项目模拟范式与该论文一致**，同时直接佐证本项目 WiFi/UDP 链路的真实性。
- arXiv:2509.25667（2025，Transformer 运动想象分类驱动轮椅仿真）；arXiv:1208.5024（2012，脊髓损伤受试者脑控外骨骼，离线准确率 86.3%）。
- 来源：arXiv 检索（`"brain-computer interface" AND wheelchair`，共 21 篇相关结果）。
  http://export.arxiv.org/api/query?search_query=all:%22brain-computer+interface%22+AND+all:wheelchair
- ⚠️ 注：曾考虑的 arXiv:2410.09763 已被作者撤回（含过时数据、结果不一致），不引用。

**结论：** ① 轮椅相关需求人群规模巨大且持续增长；② 电动轮椅成本高、接口封闭，而 BCI 是行业公认的差异化方向；③ 「脑电→意图→运动指令」闭环有多篇国际文献佐证。三项证据共同支持本项目「低成本、接口开放、可教学的脑控轮椅软件链路」定位。

**备注（未验证假设，不作来源事实）：**
- H1：轮椅使用者对「更少肢体动作操控」的主观偏好（需访谈/观察补充，可选做）；
- H2：脑控痛点可被低成本方案缓解（由 3.2 成本数据间接支撑，未实测）；
- H3：模拟脑电信号足以验证本软件链路（本项目核心假设，须联调实测）。

## 4. 现有方案与差距

| 现有方式 | 局限 | 本项目定位 |
|---|---|---|
| 手动轮椅 | 需体力与上肢功能 | 探索低体力脑控输入 |
| 电动轮椅（摇杆） | 对手部功能有要求、成本高 | 以 SSVEP 意图选择替代摇杆 |
| 商用脑控方案 | 脑电帽昂贵、接口封闭、不可教学 | 协议开放、成本趋零、可教学 |

**差距：** 缺少低成本、接口开放、可教学的脑控轮椅软件验证方案，能演示「意图→指令→运动→状态回显」闭环。

## 5. 拟议方案与技术路线（对齐协议草案 v0.2）

### 5.1 三段链路

> **模拟说明（重要）：** 本项目是**软件模拟**，真实系统「脑电帽 --蓝牙--> 处理端」这一段，在模拟阶段**替换为 WiFi UDP 9000**（A 手机代替脑电帽、走 WiFi 而非蓝牙），仅为了让三台设备同网、演示简单。蓝牙通道本身按真实链路保留协议预留（`docs/bluetooth-protocol-BrainchairAPP.md`），供后续实体脑电设备接入时使用。

```
【本项目模拟链路】（协议草案 §1~2）
A 手机(模拟脑电帽) --WiFi UDP:9000--> B 手机(处理端上位机) --WiFi UDP:9001--> C 电脑 Unity(虚拟轮椅)
                          (脑机帧 10Hz)                          (指令帧)        │
                                                 可选状态回传 (状态帧 UDP:9002, 5Hz) ←─┘
```

三端职责（协议草案 §3）：
- **A 手机（采集端模拟）**：模拟 SSVEP 解码器输出——注视闪烁目标（前/后/左/右/停）选出的**意图指令码 + 置信度 0~100**，经 UDP 9000 发**脑机帧**（真实链路此段为蓝牙，本项目统一走 WiFi 以简化组网）；
- **B 手机（处理端，核心）**：收脑机帧 → 校验 → 提取意图与置信度 → 置信度判定（低于阈值拒绝、高于阈值转发）为控制指令（真实系统此处跑 SSVEP 频率识别模型，本项目简化为置信度判定）→ 经 UDP 9001 发**指令帧**；任何模式下**急停优先**；
- **C 电脑 Unity（执行端）**：收指令帧 → 驱动 3D 轮椅位移/转向/轮子旋转 → **1 秒收不到合法帧自动停车** → 可选回传**状态帧**。

### 5.2 统一帧格式（协议草案 §2，三端共用）

| 字段 | 帧头 | 帧类型 | 数据长度 | 数据区 | 校验 | 帧尾 |
|---|---|---|---|---|---|---|
| 字节 | 2 | 1 | 2 | N | 1 | 2 |
| 示例 | `0xAA 0x55` | 脑机帧`0x01`/指令帧`0x02`/状态帧`0x03` | 高字节在前 | 见下 | XOR 或 CRC8（待锁定） | `0x0D 0x0A` |

- **脑机帧（A→B）数据区 7B**：意图指令码（`0x01`前进/`0x02`后退/`0x03`左转/`0x04`右转/`0x05`停止）、置信度(0~100)、预留字节、秒级时间戳(4B)；
- **指令帧（B→C）数据区 4B**：指令码(`0x01`前进/`0x02`后退/`0x03`左转/`0x04`右转/`0x05`停止/`0x06`急停)、速度(0~100)、转向强度、序列号(0~255 循环，用于丢帧统计与去重)。

### 5.3 SSVEP 意图→指令的置信度判定（脑控模式，示例，协议草案 §4）

```
置信度 < 30          → 拒绝执行（模拟误判/信号差），发 0x05 停止
置信度 ≥ 30          → 转发意图指令码（0x01~0x05），
                      速度 = (置信度-30)/70*100（0~100 线性，仅前进/后退有效）
急停 0x06            → 仅由 B 端急停按钮触发，不进脑机帧
```
> 初始示例值，M3 联调后校准；判定函数集中一处代码，便于调整；意图切换需连续 3 帧（约 300ms）确认（对应真实 SSVEP 驻留时间）。

### 5.4 安全机制（协议草案 §5，模拟「像真实轮椅」的关键）

| 机制 | 模拟方式 | 对应真实系统 |
|---|---|---|
| 帧校验 | 每帧带校验字节，校验失败丢弃并计数 | 防止错帧误动作 |
| 急停优先 | 任何模式按急停 → 立即发 `0x06`，10Hz 连发 3 次确保送达 | 真实轮椅急停开关 |
| 超时停车 | C 端 1 秒收不到合法指令帧 → 自动停车 | 指令丢失时轮椅必须停下 |
| 断链提示 | B 端 1 秒收不到脑机帧 → 界面提示「信号丢失」，C 端自动停车 | 脑电帽脱落警示 |
| 手动接管 | 手动操作瞬间关闭信号接收、优先执行手动指令，30 秒无操作后恢复（见 `docs/simulation-safety-design-BrainchairAPP.pdf` §4） | 手动模式与脑控模式互斥 |

### 5.5 Unity 3D 场景与扩展预留

- **Unity 执行端**：3D 虚拟轮椅按指令运动（位移/转向/轮子旋转），零预算建模（Unity Terrain 刷坡挖坑、Raycast 探测），含**平地/坑地/爬坡/下坡**四类场景（详见 `docs/simulation-safety-design-BrainchairAPP.pdf` §5）：
  - 坑地：射线探测到坑 → 自动停车；
  - 爬坡：坡度超阈值 → 停车提示；
  - 下坡：强制限速；
- **蓝牙串口预留（蓝牙协议草案 v0.2，见 `docs/bluetooth-protocol-BrainchairAPP.md`）**：B 手机预留在 WiFi 模拟之外的第二输入源——蓝牙串口（经典 SPP / BLE UART 透传），以「输入源抽象」接入统一脑机帧流；**模拟阶段不依赖蓝牙协议**（该段替换为 WiFi UDP 9000），未来接真实脑电设备（NeuroSky/OpenBCI 等）只需新增适配器，核心逻辑零改动；蓝牙断开视为信号丢失，复用超时停车机制（详见 PDF §3.1）。

### 5.6 MVP 用户任务

脑控模式下注视闪烁目标 → 轮椅按意图运动（前/后/左/右/停）；手动方向键转向；任意时刻可急停；断链自动停车；状态页实时显示速度/运行状态。
