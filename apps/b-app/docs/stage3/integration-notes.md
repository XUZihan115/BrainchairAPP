## 本次确认的接口

- 来源：[Unity 提供的原文](udp-9001-interface-source.md)。原文件 SHA256：`c632789f13a5e4bd63e7f12ea75abf3461e103f4304d413c45f285d70092d717`。
- 文档是 Unity 负责人对实际代码的说明；当前 B 工作目录没有该 Unity 工程源码，不能声称已直接编译或运行其 C# 接收器。
- 用户随后明确“已从 4 s 改为 1 s”，因此 **Latch 租期按 1 秒协定**。原文保留 4 秒内容作为来源记录；B 每 200ms 重发运动指令。真实 Unity Inspector 值和断网停车效果仍需运行时联调核验。
- A 端最新约定为按住持续发送、松手 STOP、换方向结束旧流再发 INFO。独立发送器可模拟该路径；没有修改或证明已有 A APK 已遵循最新约定。

命令发往 Unity IPv4:9001，状态在 B 的 9002 接收。B 接收 A 的发现请求也使用本机 9001；Unity 发送使用独立临时源端口，二者没有占用同一个监听套接字。

```
AA 55 | 01 | DATA长度(1字节) | CMD [SPEED] | Sum8(TYPE+LEN+DATA) | 0D 0A
CMD: 前01 后02 左03 右04 STOP05 ESTOP06
```

运动发两个数据字节，速度 1–100；STOP/急停发一个数据字节。UI 可设 0–100，但设 **0 会撤销运动并发送 STOP**：Unity 对运动帧中的 0 是“保留原速度”，不能用它实现零速停车。没有 0x07，也不发送解除急停字符串。

反馈严格要求 22 字节、TYPE03、LEN15，按小端解析有符号线/角速度、位置，以及无符号 32 位时间。二进制数据中的 CRLF 不作为截断标志。只接收配置 IP 的合法帧，重复/迟到状态不刷新在线计时，1 秒无新合法状态显示离线。状态是遥测，没有逐包确认语义；显示“本机已发”不等于对端执行。

原文状态示例最后校验 `CE` 有误：按公式应为 **D0**。解析器拒绝 CE，并有独立构造和黄金报文测试；没有照抄该示例错误。

## 操作与控制优先级

1. 输入 Unity 电脑 IPv4 和速度，保存；点击“开始监听”启动前台控制服务。未配置 IP 不发送任何 UDP，不显示假发送成功。
2. 手动模式无需 A：四方向按钮触发 Latch 持续控制，普通停止结束。EEG 只做分析和显示，不能覆盖手动方向。A 的 STOP 不接管手动模式；全局人工 STOP、急停、远端故障仍有效。
3. EEG 模式以当前流的真实 CCA 门控、稳定判决驱动统一出口。模式/目标切换立即禁止新运动，在发送线程依次发旧端STOP、应用配置、发新端STOP；切换完成才接受新操作，不缓存切换期间的运动。进入 EEG 后需新的 INFO；新方向未识别前保持 STOP。普通停止后不自动恢复旧方向。
4. 数据错误、缺包/窗口失效、判决/输入过期或 STREAM_STOP 通过原有失效通知撤销 EEG 最终输出。发送线程每次读取当前状态，不排队保存旧运动帧；旧异步计算不能覆盖停止/新流。
5. 人工急停立即锁定 B，06 连发三次，目标间隔 30ms；此后只发 STOP 保活，B 仍锁定。这样 Unity 操作者按 Z 时不会被不断重复的 06 重新锁上。任一新的急停操作可再次触发三连发。
6. 恢复步骤：先让 B 收到 Unity 已锁定的反馈；Unity 人工按 Z；收到 500ms 内的新鲜、静止、无故障且已清除急停的状态；再在 B 点击“确认Unity Z解除”。B 同时核对急停三连发已结束及反馈晚于最后一个06。不自动恢复运动，仍需新流/新手动操作。
7. B 的急停锁存持久化到本机设置。普通 STOP、切换模式、新 INFO、重启服务不会解除它。已知 Unity 故障会阻止运动，清故障后也需新控制输入。

反馈不作为每条命令的 ACK，单纯反馈超时只影响连接显示；EEG 输入/识别有独立 1 秒过期机制。没有反馈时可以测试普通手动控制，但不能在 B 解除急停。正常运行的发送、切换及退出STOP均由独立发送线程执行，避免界面线程网络限制。协议没有序号或 ACK，因此不能由 B 消除所有网络重排/丢包风险；Unity 的 1 秒租期与急停锁存必须独立生效。

## 正式识别配置

`SignalTiming`：窗口 **2.5秒**、滑动更新 **250ms**；沿用 500ms 因果滤波预热、4–45Hz 连续滤波、原9通道、四频率3谐波 CCA，门限 **0.65/0.15**、三窗投票、300ms去抖。方向顺序前/左/右/后与协议前/后/左/右分别映射，没有直接用标签驱动控制。

500ms预热+2500ms窗口，最早约3秒得到原始门控判决；250ms间隔三窗通常最早3.5秒稳定。继续按住后，只更新滑动窗口，不反复清空重等3.5秒；新流才重置。生产调度和设备负载会再增加耗时。仍保留拒识和超时，不代表真实脑控安全验收通过。

原四窗口实验入口只适配了新的显式参数接口，4秒数值校验仍显式使用4秒；没有重跑整批历史比较或改写历史结果。
