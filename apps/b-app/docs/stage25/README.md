# Stage 2.5：APK 内 EEG 回放的独立验证

日期：2026-10-19。分支 `codex/b-stage2p5-validation`，从 Stage 2 提交 `467f106` 创建。Stage 1/2 分支和产物保留；团队仓库未修改，未推送。

**结论：回放验证已执行，正式阈值标定尚未通过。** B 端确实从原始 EEG 计算 CCA，16 个运动试次的对齐诊断窗方向均正确，但连续窗口的覆盖率显著下降。候选阈值在完整静息拼接场景出现误动，不能作为正式参数。没有修改生产滤波器、门控、UDP 协议或 App 默认阈值；本阶段新增的是可复现验证、统计及记录。

## 2. 测试如何避免替代算法和标签泄漏

`ReplayValidationTest.kt` 通过独立测试组包器构造正常 UDP v2 字节，交给实际 `StreamSession` 和 `SignalEngine`，由实际 `Bandpass`、`Cca`、`DecisionGate` 计算。没有另写 Python EEG 分类器，也未使用 A 端 `acceptance_probe.py` 作答案。

标签和原始资产下标只在测试发送/评价代码中选择数据、计算结果；进入生产识别器的内容只有标准原始 EEG 报文。生产算法看不到按钮、标签或试次来源。标定扫描调用实际 `DecisionGate` 处理 B 端输出分数。

三种口径严格区分：

1. **单独4秒试次后停止**：18/18 均未形成可判决窗口，因为预热0.5秒后还需完整4秒。记录为窗口不足，不算分类错误也不算识别成功。
2. **单试次对齐诊断**：同一 Bandpass/Cca 对4秒输入计算，用于频率映射和参考分数对照；不经过完整预热、投票，不能当作端到端成绩。
3. **完整连续流水线**：每5ms输入5个62通道样本，每200ms运行实际引擎，保留跨包滤波状态，跨4秒试次边界和硬回绕，不使用标签重置滤波器。STOP、新 INFO、丢包和超时则按生产逻辑重置。

## 3. 预先划分与阈值结论

在查看 CCA 分数前固定：每方向按资产顺序前2段 + 第一段静息用于标定，其余用于评价。两组各9段、36秒；状态不跨组，跨组窗口不参与调参。每个方向的两段连续拼接循环3遍（24秒），每组唯一静息段循环3遍（12秒）。循环产生重叠窗口，**不增加独立样本数量**。

固定窗长4秒、步进200ms、预热0.5秒、连续3票、去抖300ms。只扫绝对门0.45–0.85、差值门0.05–0.35，均步长0.02（336组）。选择规则：标定窗口中错误运动和静息误动均为0，再最大化正确运动输出数；并列优先较大的阈值和。这是小样本探索规则，不是安全认证标准。

得到实验候选 **绝对门0.55、差值门0.05**。在评价数据前冻结；没有用评价误判再次调参。候选没有减少窗长、预热、投票或停止约束，但相关值门槛低于原调试值，必须接受额外安全评价。结果不支持推广部署，因此**未修改 App 默认0.65/0.15**；默认值也仍未完成真实使用标定。

| 配置 | 评价运动有效窗 | 正确输出 | 错误方向 | 拒识停止 | 评价静息误动 |
|---|---:|---:|---:|---:|---:|
| 原默认0.65/0.15 | 392 | 173 | 0 | 219 | 0/38 |
| 冻结候选0.55/0.05 | 392 | 226 | 0 | 166 | 0/38 |
| 参考0.57/0.245 | 392 | 151 | 0 | 241 | 0/38 |

候选运动覆盖率226/392=57.65%，拒识42.35%。不能只用“输出过的方向均正确”宣布100%准确率。单组仅4秒真实静息，远不足以估计低概率误触发；连续时间邻近、同被试和 A 端预筛选进一步限制泛化。

进一步按 A 端文档将全部4段运动/2段静息硬拼接循环（混用两组，**只作描述性压力检查，不能再称独立评价**），候选在静息58个有效窗口中出现 **2次后退误动**。因此本次无法提供可靠的正式标定参数。需要新增独立、较长的静息与方向数据，再冻结新的标定/测试划分；不在已看过的评价集上反复调到100%。

逐段四分数、原始/稳定混淆矩阵及 CCA 范围见 [数值结果](RESULTS.md)；CSV见 [逐段结果](segments.csv)。完整每200ms记录保留于 `output/stage25/windows.csv`，含真实标签、段号、窗口尾、四分数、argmax、门控原始判决、稳定判决、原因和计算耗时。

离线CSV的 `cpuMs=0` 是未注入JVM CPU计时器的占位值，不表示算法不耗CPU；CPU测量只采用实际Android进程记录。

## 4. 失败记录与安全边界

所有错误运动窗口见 [errors.csv](errors.csv)，不能从汇总中删除。

- **静息拼接误动**：候选参数、`a-wrap-stop`，12.6秒和12.8秒输出后退。四分数分别约 `[0.3416,0.2923,0.2607,0.5607]`、`[0.3298,0.3282,0.2406,0.5602]`；窗口跨静息试次边界。原默认在同一场景无稳定误动，但这不是安全性证明。
- **不发STOP的方向切换**：依次每8秒前→左→右→后→静息，候选出现17个错误运动窗口及6个静息运动窗口；原默认仍有11个错误运动窗口。候选在左转开始后0.2–1.0秒仍输出前进，右转开始后0.2–1.2秒仍输出左转，后退开始后0.2–1.2秒仍输出右转；静息开始后0.4–1.4秒出现后退。旧信号占据最近4秒窗口，算法没有收到外部切换事件。不能靠发送端标签暗中消除此现象。
- **松手STOP与重新推流**：每个回放场景的STOP断言通过；带STOP/新INFO的独立方向场景无残留方向输出，必须重建窗口。后退8秒内可能仍未稳定识别，不能将延迟记为0。
- **降质**：向评价前进数据叠加确定种子的高斯噪声。原始数值单位标准差10时98个有效窗中59次正确、39次停止；50、100、1000时各98/98停止，无错误运动。全零18/18停止。仅证明这些可复现加噪条件，不代表所有肌电、眼电、坏电极或真实信号质量问题都能拒识。
- **丢包/超时/恢复**：主动省略样本包后窗口重建期停止；1.001秒无数据后会话清空；同一引擎新INFO清空旧状态，重新输入后形成新分数。原 Stage 2 的判决线程卡住、缓冲覆盖等回归测试继续通过。

没有采用缩短窗口、延长保留旧方向、跳过拒识等方法“修好”结果。上述问题目前属于需明确的系统边界和数据/参数不足；尚不能宣布完整安全控制验收通过。连续脑控由运动转静息时没有松手事件的情况，后续安全层和额外数据评估必须覆盖。

## 5. 时延与 Android 测试的含义

离线按采样时钟的首次稳定正确判决：候选前进5.0秒、左5.0秒、右7.4秒、后8.4秒；默认后退12.2秒。单4秒按压无判决。它们是该固定序列上的观察，不是所有试次时延上限；循环重复提供了更长时间，不能当作更多独立试次。

Android模拟器实际安装 B APK，以 Python 从资产发送62通道UDP波形，测试了保留评价数据和额外完整静息拼接。**未安装操作 A App，也不是 A/B 两台真机联调。** 模拟器窗口位置受真实调度影响，不能要求与固定200ms离线窗口逐项相同。Android完整静息短测未观察到稳定误动，但有门控原始后退判决，不能据此否定离线误动或批准候选。

Android墙钟耗时、实际判决周期、CPU、内存、收包及STOP观测见 [Android报告](ANDROID.md)。日志轮询本身存在延迟，STOP时间按外部观测上界报告，不冒充协议内部最坏时延。

## 6. 与 A 端参考结果的差异

A 手册给出的对齐窗目标相关均值约0.736、参考阈值0.57/0.245来自特定理想滤波口径；本次同一 B 滤波器的对齐诊断均值为0.73384，16个运动 argmax 均匹配。但完整滑动窗口中，评价后退最高相关中位数仅0.4639，低于其对齐窗分数；原参考阈值只输出151/392个运动窗口。

可能原因包括：因果四阶两SOS与理想FFT/逐窗IIR的差别、跨试次相位和基线跳变、循环边界、连续状态、窗口偏移、预热和连续投票。手册本身也记录过滑动窗下降与滤波器差异。没有原始 A 端参考运行日志和可靠参考程序结果，不能将差异归咎于某个唯一因素；更没有运行疑似有Bug的验收器来“证明”B正确。
