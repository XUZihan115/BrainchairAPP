|---|---|---|
| A→B 输入 | UDP v2 原始 EEG；B 后续滤波、CCA | PRD/Proposal：10Hz意图+置信度，AA55/XOR或CRC8，已被本轮明确替代 |
| A端操作含义 | 公开EEG数据回放，当前测试使用合成包 | 课程文字“注视即可控制”不能描述当前回放系统的实际能力 |

| 指令编号 | 本阶段不产生动作指令 | 旧前/后/左/右=1/2/3/4、停5、急停6；新草案停0、前1、左2、右3、后4，不能混用 |
| 置信度 | 第二阶段CCA相关值、双门控，阈值重标 | 旧30阈值和线性速度映射不适用；CCA相关值不是心理专注度或已校准概率 |
| 手动模式 | 保留需求，第三阶段实现 | “关闭接收、30秒自动恢复”与持续滤波/显式授权恢复的关系待小组确认；本轮不擅删也不实现 |
| 急停 | 保留需求，第三阶段与C定义 | 指令编号、重复发送节拍、锁止及人工解除、重连后状态均待冻结；当前停止监听不是急停 |
| 断链 | 第一阶段实现接收超时与窗口失效提示 | 双端停车、有效决策时限、设备断电看门狗属于后续；不宣称已有真实安全闭环 |
| 300ms指标 | 不能作为当前EEG端到端识别结论 | 4秒窗口与冷启动至少4秒；旧PRD原文主要写“指令到运动”，需分别定义采样→识别、指令→运动和急停延迟 |
| 蓝牙 | 需求保留，第四阶段确认范围；旧SPP代码原样留存 | SPP/BLE UART连接+数据展示是否必验、设备/协议未定；旧AA55不兼容EEG v2 |
| 状态显示 | 第一阶段显示数据链路、元信息与异常 | Unity速度/位置回显在PRD同时出现必需/可选描述；B→C及C→B都待确认 |
| UI | 本轮调试页，后续交给UI同学 | 三页设计仍保留为整合需求，不为视觉设计重构本轮接收链路 |
| 团队分工 | 用户独立负责B，Codex实现与测试 | Proposal的B端两人、旧团队计划A–E分工不作为现行安排 |
| 算法结论 | 4秒连续窗口、阈值需用实际实现重标 | 原验收器有源码问题；历史零误判、2秒“无解”等只适用于所测数据/方法，不能推广为普遍保证 |
| 验收真实性 | 自动结果附原始记录，人工验收仍由用户/小组负责 | 不以AI生成声明、A端自述或一次构建成功替代项目验收 |

1. A端实际APK/版本及可联调手机；B端安卓手机型号与系统。当前只有API35模拟器验证。
